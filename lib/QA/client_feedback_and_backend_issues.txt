⚠️ 2. Key Findings from Our Backend & Infrastructure Audit:
--------------------------------------------------------------------------------
During our deep review of the backend architecture (Supabase DB, RLS, Stripe & Checkr integration), we identified critical gaps that must be implemented on the backend to achieve production readiness:

1. 💳 Stripe Webhook Listeners are Missing (High Risk):
   • Payments currently rely on browser redirects. If a parent closes the tab before redirecting, the booking in the database remains unpaid.
   • Missing dispute/chargeback webhooks mean the backend will not detect when a parent disputes a charge with their bank.

2. 🔄 Commission & Payout Split Math Needs Server Authority:
   • All fee calculations (Gross, Sporve Platform Fee %, Org Commission, Net Payout) must be executed by Supabase Edge Functions pulling directly from DB tables—never calculated on the client device.

3. 🛡️ Checkr Background Verification is Currently Manual:
   • The system lacks an automated webhook endpoint to receive Checkr screening results and update coach status automatically with service_role permissions.
   • FCRA legal adverse action email flow (pre-notice, report copy, waiting period, final notice) must be templated on the backend.

4. 🗄️ Database-Level Safety Gating (match_eligible):
   • Gating must be enforced at the database/RLS level so setting a coach to unverified instantly excludes them from search, matching, and API bookings.

5. 🔔 Push Notification & Reminder Triggers:
   • Need backend triggers/cron for chat messages, booking confirmations, and scheduled session reminders (24h and 2h before session start).

PART 2: DETAILED TECHNICAL BACKEND SPECIFICATIONS & AUDIT FINDINGS
================================================================================

--------------------------------------------------------------------------------
1. STRIPE PAYMENT WEBHOOKS (CRITICAL — LAUNCH BLOCKER 🔴)
--------------------------------------------------------------------------------
Audit Finding: The system currently relies on client-side returns. The backend must be the single source of truth for payment state.

[ ] checkout.session.completed Webhook Handler:
    - Backend listener for parent payment completions.
    - Webhook must flip bookings.status to 'paid' and 'confirmed'.
    - PASS CONDITION: Parent pays, immediately closes browser tab before redirect; 
      booking status in Supabase still transitions to 'paid'.

[ ] charge.dispute.created Webhook Handler:
    - Backend listener for chargebacks/disputes.
    - Update booking row to status = 'disputed', dispute_status = 'needs_response'.
    - Trigger immediate push notification and email alert to coach and admin.

[ ] charge.dispute.closed Webhook Handler:
    - Update booking DB status to 'chargeback_won' or 'chargeback_lost'.

[ ] payment_intent.payment_failed Handler:
    - Release reserved time slots immediately to prevent orphaned locked slots.

--------------------------------------------------------------------------------
2. STRIPE CONNECT & SERVER-SIDE COMMISSION MATH (CRITICAL — LAUNCH BLOCKER 🔴)
--------------------------------------------------------------------------------
Audit Finding: Client-provided fee calculation is insecure. Fee splits must be computed server-side.

[ ] Server-Side Checkout Session Edge Function (create-checkout-session):
    - Edge function pulls platform fee % and organization commission directly 
      from Supabase tables (organizations, coaches, bookings) to compute 
      exact transfer splits server-side.
    - The client app must never supply fee math.

[ ] Provider Payout Engine (stripe-provider-payouts):
    - Edge function triggering transfer/payout to coach Stripe account upon 
      verified session completion.

[ ] 1099-K Tax Compliance Setup:
    - Configure Stripe Connect Custom/Express accounts to issue 1099-Ks for 
      providers exceeding statutory limits.

--------------------------------------------------------------------------------
3. CHECKR API & BACKGROUND CHECK WEBHOOK PIPELINE (CRITICAL — LAUNCH BLOCKER 🔴)
--------------------------------------------------------------------------------
Audit Finding: Manual status flipping is a compliance and safety liability. Automation is required.

[ ] Checkr Screening Invitation Edge Function:
    - Automatically create Checkr candidate and send background check invite 
      when coach completes Step 2 of onboarding.

[ ] Checkr Webhook Handler Function:
    - Supabase Edge Function to receive background check report webhooks from Checkr.
    - Automatically update coaches.background_check_status ('verified' or 'consider') 
      using the Supabase service_role key.

[ ] FCRA Adverse Action Workflow:
    - If a check disqualifies a coach, trigger automated email notices: 
      Pre-adverse action notice + copy of report -> statutory waiting period -> final notice.

--------------------------------------------------------------------------------
4. SERVER-SIDE SAFETY GATING (CRITICAL — LAUNCH BLOCKER 🔴)
--------------------------------------------------------------------------------
Audit Finding: Client-side gating must be backed by database RLS/views.

[ ] Database Gating View / RPC (match_eligible):
    - Enforce safety gating at the database level:
      match_eligible = (background_check_status == 'verified' AND is_active == true)
    - PASS CONDITION: Manually set a coach to unverified in DB; coach instantly 
      disappears from search, AI recommendations, and direct-booking endpoints.

--------------------------------------------------------------------------------
5. TRANSACTIONAL PUSH NOTIFICATIONS & REMINDERS (HIGH PRIORITY 🟡)
--------------------------------------------------------------------------------
[ ] Automated Notification Triggers (FCM / Edge Functions / Database Webhooks):
    - New Chat Message: Push notification dispatched to recipient when offline.
    - Booking Confirmed / Paid: In-app notification and email receipt.
    - Scheduled Session Reminders: Automated cron notifications at T-24h and T-2h.
    - Cancellation / Reschedule: Instant push notification and refund trigger.
